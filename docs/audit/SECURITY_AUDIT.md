# Sakina – Security & Privacy Audit

Audit date: 2026-11-17. Static review only: no penetration testing, no traffic interception, no binary reverse engineering. No secret values are reproduced in this document. Finding IDs are defined in [COMPREHENSIVE_AUDIT_REPORT.md](COMPREHENSIVE_AUDIT_REPORT.md).

## 1. Threat surface

Sakina is local-first: no accounts, no backend of its own, no remote push. The attack surface is:

| Surface | Exposure |
|---|---|
| Bundled content (Quran, hadith, adhkar) | Integrity (hash gate in CI) and authenticity (owner approval pending, REL-01) |
| Network clients | api.quran.com (recitation), 4 RSS feeds, YouTube Data API, Firebase Crashlytics (opt-in) |
| Local storage | `SharedPreferences` (settings, coordinates, progress), app-support dir (recitation audio) |
| Exported Android components | `MainActivity` (launcher), `AudioService` + `MediaButtonReceiver` (required by audio_service) |
| Notification payloads | JSON produced by the app itself, parsed defensively |
| Build-time secrets | `YOUTUBE_API_KEY` via dart-define; Android signing via git-ignored `android/key.properties` |

## 3. Sensitive data handling

- **Secrets in repository**: `dart run scripts/check_secrets.dart` → "No credentials found in tracked files." `.env`, `android/key.properties` are git-ignored and untracked (`git check-ignore` confirmed). `.env.example` has an empty value. The scanner does not cover git history (README states this).
- **Firebase**: `android/app/google-services.json` and `lib/firebase_options.dart` are tracked. They contain client API keys that identify the project; they are not secrets but must be restricted (SEC-02). The JSON still contains clients for `com.example.sakina_app` and `app.sakina.quran` (REL-03).
- **Crash reports**: only `error.runtimeType` and the stack trace are sent (`monitoring_service.dart:112-119`), opt-in, default off (`monitoring_enabled`), native auto-collection disabled in both manifests (`firebase_crashlytics_collection_enabled=false`, `FirebaseCrashlyticsCollectionEnabled=false`). Good.
- **Location**: coordinates stored in prefs (`prayer_latitude/longitude`), never sent over the network (verified: no network client receives them; prayer times and qibla are computed locally). iOS compass starts location updates only while the Qibla screen listens.
- **Logging**: `developer.log` messages include prayer names and times, not coordinates; `BootReceiver.kt` logs actions with `Log.d/i` (harmless).

## 4. Network security

- All endpoints in code are `https://` (`grep` of `lib/`). Android target SDK ≥ 28 blocks cleartext by default; no `networkSecurityConfig` or `usesCleartextTraffic` overrides. iOS has no ATS exceptions.
- Recitation URLs from the API are accepted only if they start with `https://` (`quran_cdn_recitation_source.dart:51`).
- Timeouts: 15 s for media, explicit timeouts for recitation; location 30 s.
- The YouTube key is sent in the `X-Goog-Api-Key` header rather than the URL, so it does not appear in exception text (`video_remote_datasource.dart`).
- No certificate pinning (appropriate: public CDNs, no credentials in transit).
- No authentication/session management exists (out of scope by design).

## 5. Local security

- No database; `SharedPreferences` (plain XML on Android, `NSUserDefaults` on iOS). Data is non-sensitive except coordinates; encryption is not warranted, but backup rules should be explicit (PLAT-A-03).
- Recitation files live in the app-support directory (private to the app).
- Notification payloads are generated by the app; parsing tolerates malformed JSON (`notification_service.dart:435-462`); navigation validates surah range (`notification_handler.dart`) and route extras (`app_router.dart:60-73`).
- External links: only http/https with a host, launched externally after confirmation (`external_links.dart`) — blocks `intent:`/`file:`/`javascript:` from RSS.

## 6. Platform configuration

- Android: release builds fail without a real keystore (`build.gradle.kts` `taskGraph.whenReady` check); R8 enabled with keep rules; unused foreground-service types and services removed via `tools:node="remove"`; `BootReceiver` not exported; plugin receivers not exported.
- `AudioService` and `MediaButtonReceiver` are exported, as audio_service requires for media browser and hardware buttons.
- iOS: no entitlements (none needed today), `UIBackgroundModes` = audio, fetch; usage string only for when-in-use location.

## 7. Dependencies

`flutter pub outdated` lists no advisories, but pub's advisory database only covers published advisories; the core native plugins are several majors behind (DEP-01) and the transitive `js` package is discontinued. No unused network/analytics SDKs are present.

## 8. Remediation summary

1. Restrict the YouTube key by API, package/SHA-1 and bundle ID; set a quota (P5-01).
2. Align Firebase apps with the final identifiers; delete stale clients (P0-03, P5-05).
3. Remove `ACCESS_FINE_LOCATION` (P5-02).
4. Add explicit Android backup/data-extraction rules (P1-09).
5. Add `PrivacyInfo.xcprivacy` and export-compliance key (P5-03).
6. Upgrade notification/Firebase/WorkManager plugins one at a time (P5-06, P5-08, P5-09).
7. Scan git history for secrets (P5-04).
